7. RECOMMENDATION ENGINE ALGORITHMS (MATHEMATICS, FORMULAS & CODE IMPLEMENTATION)
====================================================================================================
Location: `recommendation_engine.py`

----------------------------------------------------------------------------------------------------
7.1 Content-Based Filtering (CBF)
----------------------------------------------------------------------------------------------------
Objective: Measure similarity between movie textual representations and user taste profiles.

A. Text Feature Extraction:
For each movie `m`, construct a document `D_m`:
`D_m = title + " " + genres + " " + genres + " " + overview + " " + director + " " + director + " " + cast + " " + tags`
(Notice: `genres` and `director` are repeated to artificially inflate their Term Frequency weights).

B. Tokenization & Pruning:
Tokens are extracted using regex `\b[a-zA-Z]{2,}\b`, lowercased, and filtered against an English stop-word lexicon.

C. Term Frequency - Inverse Document Frequency (TF-IDF):
For term `t` in movie document `D_m`:
$$\text{TF}(t, D_m) = \frac{\text{count}(t, D_m)}{\sum_{t' \in D_m} \text{count}(t', D_m)}$$
$$\text{IDF}(t) = \ln\left(\frac{1 + N}{1 + \text{DF}(t)}\right) + 1.0$$
where:
- `N` = total number of movie documents in the catalog (1,200).
- `DF(t)` = document frequency (number of movies containing term `t`).
- The vector is L2-normalized:
$$\vec{V}_m = \frac{\vec{W}_m}{\|\vec{W}_m\|_2}$$

D. Cosine Similarity Function:
Given two L2-normalized sparse vector dictionaries `V_a` and `V_b`:
$$\text{CosineSimilarity}(\vec{V}_a, \vec{V}_b) = \sum_{t \in \vec{V}_a \cap \vec{V}_b} \vec{V}_a[t] \cdot \vec{V}_b[t]$$
Time Complexity: O(min(|V_a|, |V_b|)) due to intersection over sparse keys.

E. User Profile Generation:
User profile vector `U_u` is constructed by accumulating weighted vectors:
$$\vec{U}_u = \sum_{m \in \text{Liked}} 1.5 \cdot \vec{V}_m + \sum_{g \in \text{PrefGenres}} 2.0 \cdot \vec{T}_g$$
where `Liked` are movies rated >= 3.5 or positively interacted with, and `T_g` are token vectors of user's chosen onboarding genres. `U_u` is subsequently L2-normalized.

----------------------------------------------------------------------------------------------------
7.2 Collaborative Filtering (CF)
----------------------------------------------------------------------------------------------------
Objective: Predict ratings for unseen movies based on community user-item interactions.

A. User Rating Representation:
User `u` is represented by rating vector `R_u = {m_1: r_{u,1}, m_2: r_{u,2}, ...}`.
Mean rating of user `u`:
$$\bar{r}_u = \frac{1}{|I_u|} \sum_{m \in I_u} r_{u, m}$$

B. Pearson Correlation / Centered Cosine Similarity between User `u` and User `v`:
$$\text{sim}(u, v) = \frac{\sum_{m \in I_{uv}} (r_{u, m} - \bar{r}_u)(r_{v, m} - \bar{r}_v)}{\sqrt{\sum_{m \in I_{uv}} (r_{u, m} - \bar{r}_u)^2} \sqrt{\sum_{m \in I_{uv}} (r_{v, m} - \bar{r}_v)^2}}$$
where `I_{uv} = I_u \cap I_v` (movies rated by both users). If `|I_{uv}| < 2`, `sim(u, v) = 0`.

C. Rating Prediction Function:
For candidate movie `m` unrated by user `u`, predict score using top `K=25` nearest neighbors `S(u)` with `sim(u, v) > 0.1`:
$$\hat{r}_{u, m} = \bar{r}_u + \frac{\sum_{v \in S(u)} \text{sim}(u, v) \cdot (r_{v, m} - \bar{r}_v)}{\sum_{v \in S(u)} |\text{sim}(u, v)|}$$

D. Normalization:
$$\text{CF\_Score}(u, m) = \text{clip}\left(\frac{\hat{r}_{u, m} - 0.5}{4.5}, 0.0, 1.0\right)$$

----------------------------------------------------------------------------------------------------
7.3 Multi-Objective Hybrid Recommendation Scoring Function
----------------------------------------------------------------------------------------------------
The engine computes a composite ranking score `FinalScore(u, m)` for every candidate movie `m` not yet completed by user `u`.

Feature Components:
1. `GenreAffinity(u, m)`: Overlap ratio between user's preferred onboarding genres and movie's genres:
   $$\text{GenreAffinity} = \min(1.0, \text{Matches} \times 0.45)$$
2. `ContentSimilarity(u, m)`: Cosine similarity between normalized user profile `U_u` and movie vector `V_m`:
   $$\text{ContentSim} \in [0.0, 1.0]$$
3. `CollabPrediction(u, m)`: Predicted rating from nearest-neighbor collaborative filtering:
   $$\text{CollabPred} \in [0.0, 1.0]$$
4. `QualityPrior(m)`: Bayesian-style prior combining average rating and log-scaled rating count:
   $$\text{QualityPrior} = 0.7 \times \left(\frac{\text{AvgRating}}{5.0}\right) + 0.3 \times \min\left(1.0, \frac{\ln(1 + \text{RatingCount})}{6.0}\right)$$
5. `InteractionBoost(u, m)`: Real-time implicit/explicit interaction adjustments:
   - Added to Watchlist: `+0.25`
   - Clicked / Details Opened: `+0.10`

Linear Combination Formula:
For Established Users (with >= 1 interaction / rating):
$$\text{FinalScore} = (0.20 \times \text{GenreAffinity}) + (0.35 \times \text{ContentSim}) + (0.25 \times \text{CollabPred}) + (0.20 \times \text{QualityPrior}) + \text{InteractionBoost}$$

Match Percentage Conversion (Display on UI):
$$\text{MatchPercentage} = \text{int}\Big(\text{clip}\big(\text{round}(\text{FinalScore} \times 100), 72, 99\big)\Big)$$

----------------------------------------------------------------------------------------------------
7.4 Real-Time User Interaction Feedback & Decay Boosting
----------------------------------------------------------------------------------------------------
The system continuously listens to telemetry events from `user_interactions`:
- `like` event: Movie ID added directly to `Likes` set; positively weights user profile vector by 1.5.
- `dislike` event: Candidate movie is immediately removed from the candidate pool (`CandidateSet \ Dislikes`).
- `skip` event (progress < 10%): Recorded as a negative engagement signal (-0.20 penalty).
- `watch_progress` (25%, 50%, 75%): Increments affinity score.
- `complete` (progress >= 90%): Movie marked completed; excluded from discovery carousels and placed in "Watch History".

----------------------------------------------------------------------------------------------------
7.5 Cold-Start Multi-Stage Resolution Mechanism
----------------------------------------------------------------------------------------------------
Condition: A user has zero watch history and zero explicit ratings (e.g. immediately after registration).
Resolution Architecture:
1. Primary Driver: Onboarding genre preferences selected during first login (enforced >= 3 genres).
2. Weight Redistribution:
   $$\text{FinalScore}_{\text{ColdStart}} = (0.45 \times \text{GenreAffinity}) + (0.25 \times \text{ContentSim}) + (0.30 \times \text{QualityPrior}) + \text{InteractionBoost}$$
3. Eliminates Cold-Start Deadlock: New users immediately see a full page of high-quality, genre-aligned movies with realistic 90%+ match scores.

----------------------------------------------------------------------------------------------------
7.6 Human-Readable Semantic Recommendation Explanation Engine
----------------------------------------------------------------------------------------------------
Every recommended item is programmatically tagged with a semantic explanation string based on ranking attribution:
- Rule 1: If movie in user's watchlist -> `"In your Watchlist"`
- Rule 2: If movie has high content similarity to an explicit liked movie `M_liked` -> `"Because you liked M_liked"`
- Rule 3: If movie matches onboarding genre `G` -> `"Matches your love for G"`
- Rule 4: If movie driven by collaborative filtering -> `"Popular among users with similar taste"`
- Rule 5: Fallback -> `"Trending high recommendation"`
- Rule 6: Social recommendations -> `"Watched recently by [Friend Username]"`

   - When user watches >= 50%: Signals engagement, surfaces film to connected friends in social carousel.

11. VIDEO PLAYBACK SIMULATOR & "CONTINUE WATCHING" LIFECYCLE
====================================================================================================
Location: `static/js/player.js`

Lifecycle Execution Trace:
1. User clicks "▶ Play" on any movie card or hero banner.
2. `player.open(movie, startProgress)` launches.
3. Converts movie duration into seconds; initializes scrubber position.
4. Playback loop runs every 500ms, advancing virtual playtime.
5. Milestone Detection: When progress advances past 25%, 50%, 75%, or 90%, it triggers `api.updateWatchProgress(movie.id, pct)`.
6. Database Update:
   - Upserts record in `watch_history`.
   - If `pct >= 90%`, sets `completed = 1`.
   - If `5% < pct < 90%`, movie appears dynamically in "Continue Watching for [User]" carousel on homepage with an accurate red progress indicator bar.
7. User clicks "Finish & Save Progress":
   - Closes modal, persists exact scrubbed position.
   - Silently refreshes homepage carousels to reflect updated progress.
